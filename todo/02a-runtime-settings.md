# 02a · 设置、国际化与显示

前置：02 已有的 runtime、主菜单、暂停菜单与输入门控；本子任务的软件实现可与计时和设备准备并行，02/03 的硬件与真人体验门槛保持原样，04 的完整美术升级仍等待其前置证据

2026-10-02 从 planning 迁入正式路线图，需求已确认，设置、基础显示与 13 语言国际化已有软件交付，画质与帧率实现已通过软件与 GPU 检查；完整平台验收继续推进；未勾选表示尚未完成验收，自动检查和真实设备验收分别记录 PASS / FAIL / BLOCKED / NOT RUN

本轮完善国际化、画质、窗口与显示设置，覆盖 Windows / Linux，新增设置沿用原型菜单样式并支持键盘与手柄操作；Logo 眼睛动画不纳入本轮需求，UI 重设计继续留在 [规划区](planning.md)

先落实设置草稿、应用/取消与持久化，再接国际化、画质和窗口显示；显示预览共用设置流程，菜单输入、布局和渲染接线由主线程统一集成

## 设置流程与保存

- [ ] 从主菜单与暂停菜单进入设置，沿用输入门控，操作设置不产生游戏 Hit
- [ ] 提供“应用”“取消”“恢复默认”；应用后跨启动保存，取消丢弃本次修改，恢复默认仍需应用
- [ ] 显示变更先预览，提供 15 秒倒计时确认；取消或超时恢复原设置，确认后保存
- [ ] 设置读取失败时使用默认值并提示，保存失败时明确说明；采用原子替换保存，避免中断损坏已有配置

### 验收条件

- 键盘与手柄均可完成进入、修改、应用、取消、恢复默认和返回，不产生幽灵输入
- 应用后重启可恢复设置，取消不保存草稿，恢复默认未应用前不覆盖已保存设置
- 配置损坏、保存失败和显示预览超时均有对应检查，实际结果和错误提示一致

## 国际化

- [ ] 首批支持下表中的 13 个语言变体，覆盖菜单、HUD、设置、状态提示和玩家可见错误；品牌名称、标识符、开发日志与 CLI 不翻译
- [ ] 首次启动跟随系统语言，未支持的语言使用 `en-US`；未指定地区的 `en` 默认 `en-US`，未指定地区的 `zh-Hant` 默认 `zh-TW`；语言选项使用各语言自己的名称
- [ ] 应用语言后立即更新当前界面，无需重启
- [ ] 字体使用 Noto Sans，提供 Latin/Greek/Cyrillic 与 SC/TC/HK/JP/KR 地区字形；语言选项配下表对应的开源 SVG 旗帜，记录字体、旗帜的资源来源与再分发许可

## 画质设置

- [ ] 提供低、中、高预设及“自定义”状态；选择预设重置对应画质项，单独调整后显示“自定义”，默认使用中预设
- [ ] 独立设置包括抗锯齿、雨量、雾效、阴影与 Bloom；阴影和 Bloom 属于本轮新增效果
- [ ] 抗锯齿提供关闭、MSAA 2×、MSAA 4×；雨量提供关闭、25%、50%、100%，以当前原型密度为 100%；雾效、阴影、Bloom 提供开关
- [ ] 关闭装饰效果仍保留玩家、Anchor、输入与共同动作反馈的可读性；画质不得改变判定、SongTime 或 Replay 结果

预设初始映射如下，帧率上限、VSync 和分辨率独立于画质预设

| 设置 | 低 | 中 | 高 |
|---|---|---|---|
| 抗锯齿 | 关闭 | MSAA 2× | MSAA 4× |
| 雨量 | 25% | 50% | 100% |
| 雾效 | 开启 | 开启 | 开启 |
| 阴影 | 关闭 | 开启 | 开启 |
| Bloom | 关闭 | 开启 | 开启 |

画质软件已接入生产场景，自动检查验证预设、五项效果和核心反馈保留，46 张 1280×800 GPU 离屏截图检查通过；帧率门控直接运行生产 First 系统验证 CPU 更新间隔，独立 Session 检查覆盖有效历史窗内的不同消费批次；完整证据及实际设备验收边界见 [验证策略](../docs/testing.md)

### 帧率与垂直同步

- [ ] 帧率上限按当前窗口所在显示器报告的最高刷新率生成：每 60 一档，再追加显示器上限并去重，同时提供“无限制”；280 Hz 对应 60 / 120 / 180 / 240 / 280 / 无限制
- [ ] 默认选择显示器上限，VSync 默认关闭，两项独立控制；实际帧率受设备性能及当前显示模式限制
- [ ] 更换显示器后更新档位，超出新上限的有限值调整到新上限，“无限制”保持；无法读取刷新率时提供 60 / 无限制并默认 60

### 验收条件

- 各画质项实际生效，预设映射与自定义状态一致，切换预设不覆盖独立的显示和帧率设置
- 同一输入历史在不同画质和帧率设置下的规则结果一致，低画质及关闭效果时仍可识别核心反馈
- 自动检查覆盖 60、144、280 Hz 和低于 60 Hz 的档位生成、去重、显示器切换、未知刷新率和无限制选项
- 实际运行检查帧率限制与 VSync 的生效情况，记录设备、显示模式和测量结果

## 窗口与显示模式

- [ ] 提供一个分辨率下拉框和一个全屏复选框，全屏指无边框全屏，不切换显示器输出模式
- [ ] 首次启动默认窗口模式、1280×800；窗口超出可用桌面区域时缩小到可容纳尺寸
- [ ] 普通窗口下，选择分辨率请求调整窗口客户区尺寸；手动缩放后显示实际尺寸，非预设尺寸显示“自定义”
- [ ] 检测到窗口尺寸受 WM 管理且非全屏时，禁用分辨率下拉框并说明原因，渲染与布局跟随实际窗口尺寸
- [ ] WM 状态未知时允许请求尺寸，按实际结果更新界面；请求未获采纳时显示实际尺寸及提示，不按 WM 名称猜测行为
- [ ] 全屏下，分辨率表示 3D 游戏画面的渲染尺寸，等比缩放到屏幕，不同比例留黑边；UI、Logo 和文字保持实际窗口像素的清晰度
- [ ] 分辨率初始提供 1280×720、1280×800、1600×900、1920×1080、2560×1440、3840×2160，追加当前显示器原生尺寸并去重；窗口下过滤超出可用桌面的预设，全屏下过滤超出原生尺寸的预设
- [ ] 进入全屏保存原窗口尺寸，退出时请求恢复；最终尺寸以操作系统实际结果为准
- [ ] 窗口尺寸、DPI、显示器和全屏状态变化后更新布局、可选项与实际状态，保持控件可访问
- [ ] 记住窗口和全屏各自的分辨率选择，重新启动时校验其是否仍适用于当前显示器

### 验收条件

- Windows 与 Linux 分别检查窗口、无边框全屏、手动缩放、DPI 和跨显示器移动，实际尺寸与界面状态一致
- Linux 检查 WM 受控与未知状态：受控窗口禁用尺寸选择，未知状态允许请求并回读实际结果，全屏状态仍可选择渲染分辨率
- 全屏低分辨率及不同比例下画面等比缩放并留黑边，UI、Logo 和文字保持清晰，控件可访问
- 全屏退出、显示预览取消或超时、重启后显示器变化均恢复或调整到可用状态

## 实现边界

- 设置、文案和画面配置由 runtime 持有，沿用现有架构，不改 schema/core 的判定契约，不预建未来模块
- 各任务落实适合其行为的自动检查，真实平台与设备验收单独记录证据；需求确认不代表实现完成

退出条件：上述设置可用键盘和手柄完整操作，保存和恢复行为有证据，13 个语言变体与 Windows/Linux 显示场景分别通过验收，画质和显示设置不改变同一输入历史的规则结果
