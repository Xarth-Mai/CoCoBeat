# 初版平台与输入

初版平台为 Windows（MSVC）与 Linux，目标架构均为 x86-64 / ARM64，不做 32 位；当前已有 Bevy 键盘/手柄消息、菜单、玩家归属与重绑定的软件实现，真实设备验收仍为 NOT RUN；每个平台/架构分别记录构建与设备证据，不能用 x86-64 成功推断 ARM64 兼容

## 实现边界

runtime 在 Bevy 中首次读取键盘/手柄消息时记录软件观察时间，维护玩家归属、绑定与热插拔状态；这些时间戳不是硬件按键时刻；core/schema 只接收玩家身份、epoch、序号、SongTime 与逻辑 Hit，不依赖 Bevy、Windows 设备句柄或 Linux 设备路径
键盘与手柄走同一条 ClockBridge → Hit → DuoEngine 链路，Replay 保存相同的逻辑事实；物理设备信息可进入诊断，不能影响判定算法

Hit 由按下边沿触发，不按每帧的 held 状态重复生成。手柄枚举索引不能当作持久玩家 ID；加入/重连需要明确玩家归属，同一设备不能无意间同时控制两位玩家。
切换菜单或失焦时丢弃待消费 Hit，并保留已按下按钮的释放屏障；恢复后需释放再重新按下，避免幽灵输入；手柄断连清除归属并提示重新加入，重连后的玩家归属由菜单明确确认；长按不重复生成 Hit

## 当前操作

默认 P1/P2 为键盘 F/J；上下方向键、手柄十字键或左摇杆选择菜单，Enter/South 确认，子页用 Esc/East 返回，游戏中用 Esc/Start 暂停或恢复，F5 重新开始，F6/Select 保存 Replay；“双人输入”页集中两位玩家的加入、键盘绑定与手柄 Hit 绑定

菜单主控独立于 P1/P2，双手柄和键盘＋手柄采用同一规则：首次明确按键取得主控，该次不执行当前选项；副控普通方向、确认和返回不抢焦点，副控 Enter/Start 明确接管且只接管，释放后下一次操作才生效。菜单标题下显示当前主控和接管方式，提示不因副控 Hit 或摇杆漂移切换；左摇杆不能自动取得主控

任一已加入的手柄或键盘可以暂停，实际获准暂停的设备接手菜单，同批第二次暂停不覆盖主控；主控手柄断连会请求暂停并释放主控，下一设备明确接管后仍停在暂停状态。接管与断连保留设置草稿、显示预览和无关设备的绑定流程；绑定目标可直接应答但不取得菜单主控

已分配给同伴的手柄会被拒绝再次加入另一位玩家，并提示先解除分配；“双人输入”页为已分配的手柄提供解除入口，再按现有加入流程选择另一位玩家，可在菜单内完成键盘＋手柄的两种排列切换。解除只改变目标玩家的手柄归属，保留键盘绑定、另一位玩家和菜单主控，需释放按钮后再操作；断连使菜单行消失时保持所选操作身份，被移除的解除操作返回对应玩家的加入入口

左摇杆使用每设备独立的方向阈值与归中屏障，每次推杆移动一步，左右只调整设置，不生成游戏 Hit；切换页面时保留已按住状态，新页面需要下一次明确操作。演奏中仅已加入的手柄可暂停或保存 Replay，未加入的设备不触发这些快捷操作

玩家卡片用于进入菜单时识别设备，绑定说明同时保留为可聚焦的信息行；极小窗口中卡片可能滚出视口，键盘和手柄仍能通过信息行定位、分页读取完整绑定

菜单按真实阶段显示动作：Ready 提供开始、双人输入、设置和退出；暂停以继续为首项，另有重新开始、主菜单和未保存时的 Replay 保存；结束或故障以重新开始为首项，保存成功后移除重复保存入口。快捷键沿用同一可用性，菜单保存会阻断本批剩余确认，演奏中的 F6/Select 保存仍保留同批 Hit

焦点切换立即更新选中行、文字和操作，描边以 160 ms 的亮度反馈收尾；`Starting` / `Pausing` 在状态面板顶部显示短等待标记，收到真实阶段变化后消失，歌曲进度仍直接取 SongTime。装饰反馈不移动布局、不淡化文字、不延迟确认，也不参与菜单主控选择

完成页从已记录 Hit 与 core 已确认事件汇总双方 Precise / Good / LateOrEarly / Miss、Free Sync 和 Anchor Sync 次数，Replay 的成功路径或失败原因单独呈现；故障后重试保存保留原播放错误，结束后的保存失败仍停在结束状态。显示预览期间发生故障会在设置标题中提示，草稿、预览倒计时和安全回退继续有效

Main menu 先保存当前 Replay，再停止歌曲并重置会话，保留玩家输入绑定和设备归属；返回 Ready 后从静止段开始眼睛循环，清除这一批剩余操作，按住的确认键需释放后重新按下才能启动歌曲

每位玩家可同时使用自己的键盘与已分配手柄，支持双键盘、双手柄和混合来源的软件路径；同一手柄只能归属一名玩家，键盘冲突和保留控制键会拒绝；绑定暂不跨进程保存，真实映射和 USB/蓝牙兼容性以设备验收为准

## 交互设计依据

[《Unravel Two》PC 官方手册第 5 页](https://eaassets-a.akamaihd.net/eahelp/manuals/unravel-two-pc-en-us.pdf) 说明第二手柄加入以及键盘＋手柄的加入路径，其中 primary player 的明确职责是存档归属；手册没有证明菜单必须由该玩家独占。[Steam Input 开发者指南](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs) 要求本地多人正确接收所支持的输入路径，并建议断柄暂停；[Xbox XAG 112](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) 要求键盘和手柄数字输入完整导航、焦点与确认/返回保持一致

[《Overcooked》官方支持说明](https://steamcommunity.com/app/448510/discussions/1/1735469327937529128/) 明确给出键盘＋手柄两种排列：第一位玩家在欢迎页用自己的设备确认，第二位在 Controller Split 设置中用另一设备加入；这说明玩家归属应由明确操作决定，不能把键盘固定视为 P1

CoCoBeat 据此将玩家加入、玩法绑定与菜单控制权分别处理；首次领权、明确接管和只消费一次的策略属于本项目设计，不作为上述游戏共有规则的陈述

## 最低交互范围

- 支持双人键盘、双手柄、键盘＋手柄；允许明确加入 P1/P2。
- 每位玩家可重绑定 Hit，显示当前绑定，并处理冲突。
- 用手柄完成菜单导航、确认、返回、暂停和进入游戏，无须临时拿起鼠标。
- USB/蓝牙设备的加入、断开与重连不串玩家，不产生幽灵输入。
- 提示结合按钮/形状与文字，不只靠颜色；展示实际映射，避免跨平台硬编码设备按钮编号。

震动、专用厂商扩展等不是完成基础手柄支持的前置条件。支持范围依据实际设备/驱动验证清单，不笼统承诺所有手柄。

## Windows/Linux 分别验收

| 场景 | 证据 |
|---|---|
| 启动、图形与音频 | 干净机器正常运行，无缺失运行库；记录 OS/GPU/音频后端 |
| 双人键盘 | 同时按键、重绑定、焦点恢复不丢玩家身份；记录键盘冲突限制 |
| 双手柄 | P1/P2 独立，快速连续按下不重复或串线 |
| 键盘＋手柄 | 两种来源映射为同一种逻辑 Hit，判定一致 |
| 菜单到游戏 | 手柄可完成加入、选择、确认/返回与暂停 |
| 热插拔与重连 | 中途拔插、蓝牙重连、断开时按住按钮，不产生虚假 Hit |
| 时间与 Replay | 按设备/连接方式测量延迟，回放一致；不把事件轮询时间宣称为硬件按键时刻 |

Linux 需要核实设备访问权限、udev 与音频/图形后端，正常运行不应要求 root。Windows 使用实际映射验证主流手柄，不能以 MSVC 编译成功代替设备测试。发布时列出已验证设备与连接方式。
