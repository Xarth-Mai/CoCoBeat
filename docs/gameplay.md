# 规则与表现约束

当前 core 已实现手写 Anchor 判定、一对一 Free Sync、Anchor Sync 和有界 Resonance；自动 Anchor 与 SectionCue 尚未实现，以下初始参数的可玩性仍需真人验证

## Anchor

Anchor 表示邀请玩家共同落点的音乐时刻，当前开发歌曲在 26、30、34、38、50、54、58 秒放置 7 个手写 Anchor；未来 SectionCue 只表达结构变化，不自动要求按键，低置信度区域保留自由空间

Judge 对显式 Anchor 判定音乐相对误差：一个输入不能完成两个 Anchor，一个玩家不能重复完成同一个 Anchor。只有时间/进度水位证明机会已结束后才可确认 Miss；未匹配的自由输入没有 Miss。

## Free Sync 与 Anchor Sync

Free Sync 只表示两位玩家真实输入在时间上相近，不声称节奏在音乐上“正确”。匹配一对一、消费有稳定身份的输入，不能由网络交付顺序改变最终配对。
双方进度水位关闭相关历史后才最终确认；Anchor 按时间/id 处理，候选按距离、时间、seq 选择，Free Sync 先处理最早输入，等时按玩家/seq 排序，再选最近同伴输入；沉默不产生 Sync

Anchor Sync 同时考虑两人各自相对 Anchor 的误差，以及彼此的误差。两人同时晚 150 ms 可以表达共同动作，不能因此算作准确命中音乐。
用于 Anchor Sync 的同一对输入不能再领取第二份完整 Free Sync 奖励。

Resonance 使用已确认滚动窗口内的 `2 × 匹配对数 / 双方输入总数` 乘以有上限的活动量，输出 0–1,000 的整数值；沉默、连点和窗口过期有软件测试，是否鼓励倾听与模仿仍需真人和打乱输入对照

## 初始实验参数

| 参数 | 当前默认值 |
|---|---|
| Precise / Good / 最宽 Anchor 窗口 | ±45 / ±90 / ±180 ms，包含边界 |
| Free Sync / Anchor Sync 两人间距 | 最多 75 ms |
| Resonance | 最近 4 秒，8 对达到活动量上限 |
| 规则共享确认余量 | `2 × 180 + 75 = 435 ms` |

435 ms 用于等候可能竞争同一输入的 Anchor 和伙伴候选；实际反馈还受软件时钟余量和消费调度影响，不是固定的端到端延迟承诺；这些值尚未经过硬件校准或真人调参

## 反馈

本地 Hit 在当次输入消费时播放对应音色并触发角色形变和半环，共享确认后播放组合音色与完整环；P1/P2 使用不同轮廓、音色和声像，端到端延迟及玩家可辨识性尚未实测

表现只消费规则事实和 SongTime，不修改判定；当前手写街道随歌曲时间移动，Resonance 显示在 HUD，完整环境联动、空间 Anchor 预告和结果视图仍待实现与体验验证
